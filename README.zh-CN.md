# Token Ledger for DSH（Token 账本 · 中文说明）

一个 DeepSeek Harness 功能插件：把全部会话的 token 用量汇总成一个面板，包含累计总量、日历热力图、趋势曲线、
模型分布、逐会话用量明细，以及 CSV / JSON 导出。

数据全部来自平台自带的会话持久化服务，不解析日志文件，也不依赖任何第三方库。

## 功能

- **累计统计**——总 token 消耗，以及输入 / 输出 / 缓存读取 / 缓存写入的拆分与调用次数。
- **缓存命中率**——缓存读取占全部输入侧 token 的比例，附命中与未命中的绝对量。
- **成本折算**——按 DeepSeek 分时段价格（高峰 / 空闲）估算花费，峰谷金额分别列出。
- **日历热力图**——GitHub 风格的周列视图，或每月一个小日历；用 `周` / `月` 切换。
- **趋势曲线**——按日 / 周 / 月 / 年聚合，悬停每个时间点显示具体数值。
- **模型分布**——按用量排序展示各模型的 token 与调用次数；点击某个模型后，下方所有统计
  （热力图、趋势、成本、峰谷、会话列表）只统计该模型，再点一次取消。
- **工作区分布**——按会话头里记录的工作目录分组，回答「哪个项目最耗 token」。
- **会话用量明细**——默认只列主会话，点箭头展开它名下的子代理，卡片高度因此不会随子代理数量膨胀；
  可点表头排序，已归档会话带标记并可用复选框隐藏；范围变化时每个会话只统计落在范围内的部分。
- **分页**——每页 40 组会话，会话量再大也不会一次渲染全部行。
- **统一时间范围**——顶部过滤器是全局控制项：全部 / 今天 / 近 24 小时 / 本周 / 近 7 天 / 本月 /
  近 30 天，下方每张卡片（热力图、趋势、成本、峰谷、模型、会话、工作区）都按同一段范围重算；
  也可以自选 `起始` / `结束` 日期。
- **小时粒度**——范围缩到「今天」或「近 24 小时」时，趋势图横轴自动切换为小时，静默的小时也补
  零画出，折线不会把两段活动连成一段。
- **数据导出**——按天明细导出 CSV / JSON，或单独导出会话级 CSV（含工作区、父会话、成本列）。
- **增量刷新**——按会话的 revision 判断是否需要重新读取，刷新时只解码真正变化的会话。
- **节假日自动更新**——任意年份运行时联网拉取并缓存，跨年不必等新版本。
- **上下文操作**——输入框下方 dock 里的「清空上下文」（橙）与「压缩上下文」（绿）双按钮，
  也提供 `/clear-context`、`/compact-context` 命令。压缩可在会话运行中使用：它先定好截断点
  再让模型写摘要，压缩期间新产生的对话原样保留、接在摘要之后，检查点复用平台自带的
  「上下文已压缩」标记展示条数与 token。清空替换整个表层，因此要求会话空闲。
- **中英双语**——跟随平台语言设置。

## 环境要求

- DSH `>= 0.2.1-rc.3`（在 `dsh.engines.dsh` 中声明）。
- 使用 Web UI 的 profile；插件注册到 `sidebar.panellist` 与 `main` 两个插槽。

## 安装

在「插件」页面安装，或通过 plugin manager 指向本包目录（含 `package.json` 的文件夹）：

```
plugin_manager install_bundle target="<本目录的绝对路径>"
```

安装后侧边栏出现 **Token 统计** 入口，点击即可打开主面板。

卸载：在「插件」页面卸载 `dsh-token-ledger` 即可。

## 使用

1. 在侧边栏点击 **Token 统计**。
2. 用两个日期输入框或快捷按钮调整时间范围。
3. 热力图可在 `周` / `月` 之间切换；趋势图可在 `日` / `周` / `月` / `年` 之间切换。
4. 鼠标悬停趋势图任一数据点，查看该时间点的精确数值。
5. **会话用量** 表格默认只列主会话；点行首 `▶` 展开该会话，展开后能看到它名下所有子代理会话。
   点表头（会话 / 消耗 / 调用 / 创建时间）切换排序，取消勾选 `显示已归档` 可只看仍在使用的会话
   （该勾选状态会记住，下次打开沿用上次的选择），`导出会话 CSV` 落盘当前表格。
6. 会话较多时用卡片底部的 `上一页` / `下一页` 翻页，每页 40 组。
7. 点击 **刷新** 重新扫描，或点击 **导出** 保存按天明细的 CSV / JSON。
8. 点击 **计费设置** 打开设置窗口，修改时区、货币、峰谷时段、节假日与价目表，保存后立即重新计价。

面板打开时会自动刷新。首次扫描后，之后只解码发生变化的会话，因此历史数据量很大时也能快速加载。

## 计费配置

插件的全部计费参数都在 profile 的配置里。**在面板右上角点「计费设置」即可打开设置窗口在线修改**，
保存后立即重新计价，无需重启 DSH。

设置窗口按**结构**编辑配置，而不是按字段名逐条渲染：模型价格是一张表、峰谷是若干可复用
方案、节假日是勾选清单，通用的键值编辑器表达不了这几种形状。窗口分四个标签页：

| 标签页 | 内容 |
| --- | --- |
| **模型与价格** | 每个模型一行，未命中输入 / 命中缓存输入 / 缓存写入 / 输出四个独立价格框，峰谷开关与方案下拉，最后一列固定是删除 |
| **峰谷方案** | 可复用的时段方案：名称、自动模式、若干「起止」窗口、空闲价比例 |
| **节假日** | 系统预封装的日历，勾选即生效 |
| **通用** | 计费时区与货币单位 |

窗口底部还能**导出配置**与**导入配置**：导出的 JSON 只含计费设置（不含任何会话数据），可以分享给
他人；导入只填表，确认无误后点保存才写进 profile。

模型列表**默认列出日志里实际出现过的模型**（按用量降序），所以打开窗口就能给正在花钱的模型
定价，不用先知道模型叫什么。还没定价的模型显示「未配置」和「添加价格」按钮，点一下即建行。

**每个模型独立配置**。价目表里没有的模型使用 `defaultPrice`；面板会在成本卡下方注明
「某模型无定价，按默认价计算」，不会静默按 0 计价。

**四项价格分开计**。供应商对同一段输入的处理并不等价，所以价格表拆成四项：

| 列 | 含义 | 不单独计费时 |
| --- | --- | --- |
| 未命中输入 | 首次送入、没命中前缀缓存的部分 | 填官方标价 |
| 命中缓存输入 | 命中前缀缓存、按折扣价读取的部分 | 填 0 表示不收取 |
| 缓存写入 | 把输入写入缓存的部分 | 填 0 表示不收取 |
| 输出 | 模型生成的内容 | 填官方标价 |

缓存的这两项分开是必要的：写入是「存进缓存」，读取是「从缓存取」，两者的单价通常相差十倍以上，
合成一列会把正在预热缓存的会话算得偏便宜、把稳定复用缓存的会话算得偏贵。缓存写入也不计入缓存
命中率的分母——它是写入，不是读取。

**峰谷是独立配置项**。一个方案可以被多个模型复用：模型行的开关打开后选方案名即可。关闭开关
的模型全天按标价（高峰价）计费，因此计入「高峰时段」而不是「空闲时段」——这是它实际付出的价格。
方案改名时引用它的模型会一起改名；删除方案会留下悬空引用，此时该模型仍按高峰价计费，行内提示
「方案已删除，请重新选择」并允许重选。

**空闲价按比例算**。方案里的「空闲价比例」是标价的百分比（默认 0.5 即半价），
所以只维护一份价格表；改比例会同时重新计价高峰与空闲两个时段。

### 自动模式

「自动模式」决定一段时段的生效日期，参考闹钟响铃规则：

| 模式 | 含义 |
| --- | --- |
| 每天 | 不限星期与节假日 |
| 法定工作日（智能跳过节假日） | 周一至周五，且不在已勾选的节假日里 |
| 法定节假日（智能跳过工作日） | 只在已勾选的节假日生效 |
| 周一至周五 | 只看星期，不管节假日 |
| 自定义 | 七个星期勾选框自由组合 |

### 时段窗口

每个方案可以有多条「起始 – 结束」窗口，都用 24 小时制输入。**多条窗口是必要的**：DeepSeek 的
高峰是两个不连续的区间（09:00-12:00 与 14:00-18:00），午休按空闲价；写成一条 09:00-18:00
会把午休那段也算成高峰，高峰 token 从约 4.0 亿虚增到约 4.5 亿。

`end` 小于 `start` 时按跨零点处理，`22:00`-`02:00` 不需要拆成两条。

### 节假日

节假日日期在运行时联网拉取并缓存在 profile 下，所以跨年不需要等新版本。
只补没有数据的年份：已发布的年份不再变，尚未发布的年份（比如下一年）每天重试一次。
三个免密数据源按顺序尝试，全部失败时保留已有缓存。

插件仍内置 2026 年的日期作为初始数据，所以第一次运行、任何网络请求发出之前，计价就已经是对的。
设置里显示已加载的年数，并有一个强制重新拉取的刷新按钮。默认勾选法定节假日那一组。

内置清单只是种子数据，不是权威来源：某一年一旦拉取成功，以网络副本为准。

### 上下文操作

输入框下方的 dock 里有两个按钮，与它们作用的上下文用量环同一行：左边橙色**清空上下文**，
右边绿色**压缩上下文**。两者也是斜杠命令 `/clear-context` 与 `/compact-context`，不用鼠标也能触发。

两者的差别在于替换范围。清空取整个表层，因此要求会话空闲：改写期间追加的步骤会跟着它所依赖的
历史一起被丢掉。压缩只取**调用摘要之前**就选定的一段——终点落在最后一个不切断 tool-call/result
配对的位置——所以能在会话运行中使用，压缩期间写入的内容会原样重放在检查点之后。会话与日志
两种情况都原样保留：事件还在磁盘上，只是表层不再显示被替换的部分——这才是让出上下文窗口的那一步。

- **清空** 写入一行占位说明。它不是摘要：下一条消息之前的内容都不再保留。
- **压缩** 直接调用模型写出摘要，再用它替换那段历史。默认沿用会话的 provider 与模型，
  可在「上下文」标签页覆盖。这段历史按**原样的消息**重放给模型——同样的系统提示词、同样的
  工具定义，指令放在最后——所以 provider 的前缀缓存能覆盖整段历史，这次调用按缓存命中计价，
  不必把历史重发一遍。全程不派子代理：没有子会话、没有属于自己的工具，也就没有任何东西可改。

两者完成后，对话里会出现一条命令卡片，**不在按钮下方**再给一份重复的提示。这两个按钮的
反馈文本与统计口径完全不同：清空报告替换前后的条数与 token，压缩还会额外报告写入摘要的
字符数。它们走平台原生的 `command/run` / `command/done` 事件，所以卡片可见、可展开，
但**不进会话表层**，不会污染模型上下文。

压缩读的提示词在设置窗口的**上下文**标签页里可编辑，同一页还能指定压缩模型的
provider 与模型，留空即沿用会话的。默认提示词要求写清目标、决策及其理由、原样路径与签名、
报错原文和未完成事项，并明确禁止提及压缩本身。

同一页还有三块与「窗口还剩多少」有关的内容：

- **上下文占用** 显示当前会话按「系统提示词 + 工具定义 + 对话消息」三项算出的真实总占用，
  以及所选模型输入上下文上限、占用比例与三项分项。
- **自动压缩开关** 与 **触发阈值**（默认 75%）决定本插件在每一步开始前自己动手压缩的时机。
  同一会话的两次压缩之间至少间隔一分钟，避免「刚压完仍然超阈值」时每一步都再付一次摘要。
  触发挂在与平台引擎同一个 `agent/pre-step` 事件上，但**由本插件执行**，不写任何平台配置：
  某个 profile 完全可能禁用平台引擎（billion-context 就会把 `dsh-compaction-basic` 整行
  关掉，而 preset 内嵌行本来也改不到），那样「开关存进去了却没人生效」。判定用的是上面那
  三项真实总和，不是平台面板顶部那个按 provider usage 锚定的数字——后者在长会话里可以显示
  112K，而同一份请求实际带着 2.3M。
- **超出上限时分段压缩** 决定历史大于摘要模型窗口时怎么办。关闭：丢弃最早的部分，只把最近
  能装下的记录交给模型，并用显式标记写明丢了多少条。开启：按上限切成多段，**并行**各写
  一份摘要，再由最后一次请求整合成一份替换整段历史——不丢历史，也没有任何一次请求越过
  窗口，这正是「长对话压缩时模型无响应/返回空」的成因。
- 压缩前会先**量一次体积**。历史若已超过摘要模型窗口的 2/3，且没有开启分段，就退回到「头尾
  摘录」：开头保留目标与约束，结尾保留正在进行的事，中间以显式标记省略。被压缩的那一段
  伸进正在运行的轮次也没有关系：交给模型的就是这些消息本身，摘要正好覆盖检查点要替换的内容。
- **压缩锁在调用摘要之前**就打开，而不是之后。这样第二次请求会答「已有压缩在进行中」，
  不会为同一份摘要付两次钱，平台自己的引擎也会让路而不是与它抢。

对已经清空过的会话再次清空是空操作、按成功返回：拿一个占位换另一个同样的占位不算错误。

### 校验

所有值在保存前由平台 schema 与插件自身各校验一次：非法时区、非法 `HH:MM`、负数价格、
不在 0–1 的开区间内的空闲价比例、未知的自动模式都会被拒绝，并指出是哪一项不合法。

### 升级

1.0 的配置结构（`peakWindows` 单表、`hitPeak`/`missPeak`/`outPeak` 六字段价格、日期数组
形式的节假日）会在读取时自动迁移：高峰价成为新的标价，启用了空闲价的模型自动挂到
`standard` 方案上，日期数组折回对应的日历键。迁移是只读的，磁盘上的旧配置不被改写，
直到你在窗口里点保存。

窗口内所有文案都在 `client.js` 的 `ZH` / `EN` 字典里，两种语言各 154 个键，键集完全一致。

保存走平台的 `configEditor` 服务：它先做 schema 校验，再把整份配置写进 profile 的
`cordis.patch.yml` 并触发热重载。插件在保存前还会自己校验一次，好把错误定位到具体字段，
而不是抛一个 Loader 级的失败。若当前 profile 没有该服务或没有对应条目，窗口会退化为只读并说明原因。

> 说明：DeepSeek 的高峰规则字面是「周一至周五」，所以调休补班（周末上班）的日子仍按空闲价计算，
> 面板不会把补班日算成高峰。价格单位是「每百万 tokens」，与官方公告一致。

## 数据统计口径

- **数据源**：Host 的 `sessionPersistence` 服务列出全部会话及其不透明版本号 `revision`。版本号未变的会话直接
  跳过；变化的会话以只读方式打开并解码事件流。
- **计数**：每条带 `data.usage` 的 `assistant/message` 事件计为一次调用。总量优先取 `usage.totalTokens`，
  缺失时回退为 `inputTokens + outputTokens + cacheReadTokens + cacheWriteTokens`。
- **范围**：当前 profile 下的全部会话，包含子代理会话（`header.origin === 'subagent'`）与已归档会话；
  页脚分别统计主会话、子代理和归档数量。
- **会话标题**：从每个会话自己的 `session/title` 事件中取最后一条，不依赖可变的元数据。
- **归档标记**：读 `workspaceRegistry.archivedSessionIds`；该服务缺失时按「无归档」处理，不影响其他统计。
- **工作区**：取会话头事件（`type: "session"`）里的 `cwd`；没有 cwd 的会话归到「(无工作区)」。
- **父子关系**：取会话头里的 `parentSession`。父会话不在本次统计内时，该子代理按顶层条目展示。
- **时间桶**：按事件时间戳所处的本地日历日归类；计费额外按小时划分，小时桶用配置时区换算。
- **缓存**：折叠结果写入 `~/.dsh/storages/dsh-token-ledger/usage-cache.json`（`CACHE_VERSION = 3`），
  通过临时文件 + 重命名原子写入。
- **准确性**：总量严格等于底层 `usage` 记录之和，面板不做任何估算；会话行跟随所选时间范围，
  各会话在该范围内的用量之和与热力图对应日期完全一致；成本按小时计价后汇入日、模型与会话三个维度，
  三者的求和恒等于总量。

## HTTP 接口

Host 在 `/token-stats/api` 注册前缀路由。请求必须通过平台的 Host / Origin 校验
（`ctx.connection.requestRejection`），且为 `POST` + JSON 体。

| 方法         | 请求体              | 说明                                            |
| ------------ | ------------------- | ----------------------------------------------- |
| `summary`    | `{}`                | 返回当前快照，仅重新扫描发生变化的会话。        |
| `summary`    | `{"refresh": true}` | 强制重新解码全部会话。                          |
| `refresh`    | `{}`                | 等价于强制刷新。                                |
| `config`     | `{}`                | 返回当前配置、字段描述与可编辑状态；`models` 附 Host 实时模型目录（含各自上下文上限）。 |
| `saveConfig` | `{"value": {...}}`  | 校验并保存配置，返回保存后的配置与字段描述。自动压缩由本插件执行，不写任何平台配置，因此没有「是否同步成功」这一项。 |
| `holidays`   | `{}`                | 强制重新拉取节假日数据，返回是否变化与按年目录。|
| `clearContext` | `{"sessionId": "..."}` | 把该会话的整个表层换成一条占位说明。     |
| `compactContext` | `{"sessionId": "..."}` | 直接调用模型压缩该会话，并用摘要替换表层。 |
| `contextPressure` | `{"sessionId": "..."}` | 量一次该会话：总 token、系统提示词/工具定义/对话消息三项分项、路由模型的上下文上限与占用比例。 |

`days` 每行是 `[日期, 输入, 输出, 缓存读取, 缓存写入, 合计, 调用次数, 成本]`；
`models` 每行是 `[模型名, 输入, 输出, 缓存读取, 缓存写入, 合计, 调用次数, 成本]`；
`sessionRows` 每行是
`[会话 id, 标题, 创建时间, 是否子代理(0/1), 是否已归档(0/1), 合计, 调用次数, 父会话 id, 按天明细,
成本, 工作区, 按小时明细, 用过的模型名]`，其中按天明细为
`[日期, 输入, 输出, 缓存读取, 缓存写入, 合计, 调用次数, 成本]`，按小时明细为
`[小时, 模型名, 输入, 输出, 缓存读取, 缓存写入, 合计, 调用次数, 成本, 是否高峰(0/1)]`。
归档状态取自 `workspaceRegistry.archivedSessionIds`，归档会话的日志保留在磁盘上，
因此照常出现在 `sessionPersistence.list()` 中。

按小时明细是会话级的**最小事实单元**：整张表的每个数字都能从它推出，所以前端按范围、按模型筛选
会话时不必回 Host 再问一次。高峰标志随行下发，因为只有 Host 知道峰谷时段与节假日日历，前端自行
推算会需要同一套规则，两套规则迟早会漂移。

两个额外的按模型字段供前端做「只看某个模型」的联动，避免二次请求：

- `modelDays`：`[模型名, [按天明细…]]`，用于按时间范围重算该模型的每日曲线与热力图。
- `modelHours`：`[模型名, [按小时明细…]]`，范围缩到一天以内时用它画小时曲线。
- `modelBilling`：`[模型名, {cost, peakCost, offPeakCost, peakTokens, offPeakTokens, peakCalls,
  offPeakCalls, hits, misses}]`，用于重算该模型的成本、峰谷与命中率。

各类行统一为 14 列（带 key 的 `days` / `hours` / `models` 行为 15 列）：
`[输入, 输出, 缓存读取, 缓存写入, 合计, 调用次数, 成本, 高峰输入, 高峰输出, 高峰读取,
高峰写入, 高峰合计, 高峰调用次数, 高峰成本]`。高峰块与全量块同宽同序，所以任何一张卡只要求出
当前范围的行就能同时得到成本与峰谷占比，两者不会描述不同的时间切片。

三者的求和都与全局 `totals`、`billing` 完全一致。

界面文案位于 `client.js` 的 `ZH` / `EN` 字典，通过 `ctx.locale.register` 注册；`locale/*.json`
只承载「插件」页面显示的标题与描述。

`schemastery` 由运行时从 profile 目录解析（见 `schemaLibrary()`），**不写进 `package.json`
的 `dependencies`**：本插件以 `link:` 方式安装，包自身的依赖不会被安装，声明了反而会导致加载失败。

## 说明与限制

- 热力图、趋势与计费按配置的 `timeZone` 归类（默认 `Asia/Shanghai`，与 DeepSeek 的计费口径一致）。
- 历史很长时热力图按周生成列，超出宽度横向滚动，而不是压缩到看不清。
- 用量严格按记录的模型归类；早于用量记录功能的会话不贡献数据。
- 价目表里没有的模型按 `defaultPrice` 计价，并在「预估成本」卡片上点名提示，不会静默套价。
- 调休补班日（周末上班）按规则字面仍计空闲价；如需按补班计高峰，把峰谷方案改成「自定义」并勾上对应星期即可。
- 本插件只读取会话持久化与归档列表，注册一条 HTTP 前缀路由，并提供一个 Config schema。
- 上下文操作会改写会话表层（`compaction/*` 与一次表面替换），因此需要 `commands`、`tokenMeter`、
  `agents`、`llm` 四个平台服务；平台缺其中任何一个时，这两个按钮与命令在该 profile 里不可用，
  统计功能不受影响。日志里被替换的历史事件不会被删除。
- 压缩必须先跑完摘要才能改写，因此一次压缩的耗时取决于会话长度与所选模型；
  期间不会占住会话，可以继续对话，改写会在会话空闲时进行。
